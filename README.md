# GreenStore

Модульный интернет-магазин растений на Next.js App Router, TypeScript, Tailwind/shadcn/ui и PostgreSQL/Prisma. Завершены этапы 0–2: витрина, каталог в базе и защищённая административная панель. Оформление заказов, платежи, Telegram и перевозчики ещё не реализованы; продажи отключены.

## Локальный запуск

Требуются Node.js 24.19 (`nvm use`), npm 11 и Docker Compose для локальной PostgreSQL.

```sh
npm ci
test -f .env || cp .env.example .env
# Если .env создан из примера: задайте собственный пароль БД
# одинаково в POSTGRES_PASSWORD и DATABASE_URL.
npm run db:up
npm run db:generate
npm run db:deploy
npm run db:seed
npm run admin:create
npm run dev
```

Существующий `.env` не перезаписывайте. В подготовленной облачной среде пароль БД уже сгенерирован. Приложение использует порт 3000. База нужна для работы всех страниц; недоступность БД не подменяется демоданными.

Production-проверка: `npm run build`, затем `npm start`. Остановите запущенный production-процесс перед новой сборкой. Публикация облачной среды не создаёт публичный адрес сайта.

`db:deploy` применяет сохранённые миграции без сброса БД. `db:seed` добавляет тестовый набор только один раз, не восстанавливает удалённые категории и не перезаписывает изменения администратора. `db:migrate -- --name ...` нужен при разработке следующих миграций, не при обычном запуске. `db:down` сохраняет volume; не используйте `down -v` для данных, которые нужно сохранить.

## Административная панель

Маршрут `/admin` перенаправляет неавторизованного пользователя на `/admin/login`.

`npm run admin:create` создаёт первого администратора. Если `ADMIN_USERNAME` и `ADMIN_PASSWORD` переданы через защищённое окружение, используется эта конфигурация. Пароль — 12–128 символов. Без заданного пароля генерируется случайный, а данные локального входа сохраняются в игнорируемом файле `storage/admin-bootstrap.txt` с правами 0600. Команда не выводит пароль и не меняет существующую учётную запись. Не добавляйте этот файл в Git и не отправляйте его в чат. Повторный запуск не меняет пароль. Если создание БД-пользователя не завершилось после создания bootstrap-файла, существующий файл не перезаписывается: восстановите конфигурацию через защищённое окружение.

В панели доступны:

- Товары: создание, редактирование, категория, артикул, описания, изображения, характеристики, статус «Черновик / Опубликован / Архив».
- Варианты: отдельные цены в рублях с копейками, остатки, контейнер, вес и размеры упаковки. Удалённый из формы вариант деактивируется; история запасов сохраняется.
- Изображения: JPEG/PNG/WebP до 5 МБ и 20 мегапикселей; проверка декодированием, удаление метаданных, перекодирование в WebP и уменьшение до 2000×2000. SVG для загрузки запрещены. Первое изображение — обложка.
- Категории: создание, переименование, сортировка и удаление пустой категории. Связанные товары, включая архивные, защищают категорию от удаления.
- Настройки: название/логотип, основные тексты главной, контакты и порог низкого остатка. Ключи и токены в этих полях не хранятся.
- Обзор: данные каталога и журнал действий. Статистика продаж не имитируется.

Изменения видны на витрине после обновления страницы. Одновременное редактирование товара защищено версией: устаревшее сохранение получает 409, а не перезаписывает чужую работу.

## Данные и ограничения

В рабочей БД есть 12 демонстрационных растений и 24 варианта. Собственные SVG — иллюстрации, не фотографии товара. Новые записи можно добавлять через панель; публичная часть больше не импортирует демонабор. Корзина хранит только идентификаторы вариантов и количество; текущие цены и доступность запрашиваются у сервера. Цена не округляется до целых рублей при наличии копеек. Скрытые/архивные товары недоступны публично; сохранённая корзина сообщает об исчезнувшем варианте.

Корзина не создаёт заказ и не резервирует остатки. Кнопка оформления отключена. Показана сумма товаров; доставка не рассчитана. Вводить реальные персональные данные покупателя пока негде.

Фотографии хранятся вне `public`, по умолчанию в `storage/uploads`, и выдаются через `/media/[key]`. `UPLOAD_DIR` позволяет задать другой постоянный каталог. При резервном копировании нужны и БД, и эти файлы. Удаление фото из карточки не удаляет файл: очистка неиспользуемых ресурсов пока не реализована. Контракт `ImageStorage` позволяет позднее заменить локальное хранилище S3-адаптером.

## Проверки

```sh
npm run db:validate
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:production
```

Браузерные и production-тесты создают случайно названные временные БД и каталоги файлов, применяют миграции, создают отдельного администратора и удаляют свои данные после проверки. Роль БД должна иметь `CREATE DATABASE` (у локального контейнера она есть). Используйте локальную тестовую инфраструктуру, не производственные учётные данные. `npm run test:production` требует предварительной сборки. Для диагностики только админки: `npm run test:e2e -- --project=admin --no-deps`.

Проверено 2026-11-02: типы, ESLint, 14 тестов Vitest, 20 браузерных сценариев, сборка, повторные миграции/seed и production-сценарий с полным перезапуском приложения. Подробнее — PROGRESS.md.

## Безопасность и дальнейшая работа

Пароли хешируются scrypt с солью, токены сессий — SHA-256; cookie HttpOnly, SameSite=Lax, срок 8 часов. В production вне loopback используется Secure cookie и требуется HTTPS. На каждой закрытой странице и операции проверяется сессия; мутации проверяют Origin, вход ограничен счётчиками в PostgreSQL. `APP_URL` рекомендуется задать точным HTTPS-origin при размещении за доверенным reverse proxy. Перед публичным запуском нужны отдельные проверки безопасности, политики хранения, резервные копии, юридические документы и данные продавца.
