## Выполненные задачи
- Нормализованная схема: каталог/варианты/изображения/характеристики/категории, движения остатков, пользователи/сессии, rate-limit counters, настройки, audit и upload assets.
- Миграция с внешними ключами, индексами, уникальными slug/SKU/логинами/tokenHash и неотрицательными SQL CHECK. Перед первой миграцией создан локальный pg_dump исходной пустой БД в /tmp/greenstore-backups/before-stage2.dump.
- Одноразовый seed с audit-маркером; повторный запуск не перезаписывает товары/настройки и не возвращает удалённые/переименованные категории.
- Публичная витрина переведена на PostgreSQL repository. Новые опубликованные товары доступны по новым slug сразу. Демоданные используются только seed/tests.
- Закрытая панель /admin: login/logout, обзор реальных данных каталога, журнал действий, товары, категории, настройки. Сессия проверяется на каждой закрытой странице и каждом API, включая прямые обращения к ним.
- Пароли scrypt, случайные opaque sessions с SHA-256 в БД, HttpOnly/SameSite cookies, срок 8 часов и Secure в production вне loopback. Нет стандартного пароля и публичной регистрации.
- CLI первого администратора не меняет существующую запись. Случайные локальные данные входа сохранены только в игнорируемом storage/admin-bootstrap.txt, права 0600. Значения в инструменты и чат не выводились.
- Все административные мутации проверяют Origin/Host (и APP_URL при наличии) и Zod. Вход ограничен persistent-счётчиками глобально и по логину; истёкшие сессии/счётчики очищаются. API не раскрывает SQL и значения секретов.
- Товары: создание/редактирование, категории/артикулы, краткие/полные описания, расширяемые характеристики, DRAFT/PUBLISHED/ARCHIVED, demo/new flags и ограничения доставки.
- Варианты: индивидуальные цены с копейками, остатки, контейнер, вес и размеры упаковки. Удаление из формы деактивирует вариант. Изменения запасов и audit фиксируются вместе с товаром в Serializable transaction; версия не даёт перезаписать чужие изменения.
- Изображения: несколько фото, обложка и галерея; protected multipart upload, ограничение тела/5 МБ/20 Мп, проверка Sharp, удаление метаданных, WebP ≤2000×2000 по UUID. SVG/произвольные внешние URL запрещены. Storage interface подготовлен для замены локальной реализации S3.
- Категории: создание, переименование/slug, сортировка, удаление пустых; наличие любых связанных товаров, включая архивные, блокирует удаление.
- Настройки: имя/лого, основные тексты главной, контакты/часы/адрес, порог низкого остатка. Изменения проверены на главной, в заголовке страницы и контактах.
- Корзина получает актуальные цены/варианты с сервера и сообщает об исчезнувших/скрытых товарах. В localStorage нет цен или личных данных. Копейки больше не округляются.
- Формы недоступны до гидратации, сообщения о сохранении связаны с завершённым API. Добавлена аварийная global-error страница для сбоя базовых данных.
- Документация, архитектура, решения и повторяемые test drivers обновлены.

## Известные ограничения
- Критических дефектов в проверенных сценариях не обнаружено. Это не внешний security audit и не готовность к коммерческому запуску.
- Нет заказов/резервирования/платежей/Telegram/накладных; соответствующие таблицы/сервисы будут введены по этапам. Checkout отключён, доставка не рассчитана.
- Пока нет UI управления администраторами/смены пароля, MFA, автоматического удаления неиспользуемых фото и S3-реализации; CLI создания не заменяет существующий пароль.
- UPLOAD_DIR должен быть постоянным и включаться в бэкап вместе с PostgreSQL. Удаление изображения из карточки не удаляет файл намеренно.
- Ключи внешних сервисов не требуются. Production вне loopback должен работать по HTTPS с корректным APP_URL/reverse proxy; внешний HTTPS-сценарий в этой задаче не разворачивался.
- Для тестовых драйверов нужна локальная роль PostgreSQL с CREATE DATABASE. Не запускайте эти проверки с производственными учётными данными.
- Известные некритичные сообщения зависимостей: pg 8.23 предупреждает о queued queries внутри Prisma adapter (pg 9 не используется); Next dev иногда рекомендует eager для карточки, ставшей LCP; тестовая среда сообщает NO_COLOR/FORCE_COLOR. Проверенные операции при этом проходят.
- Global-error реализован, но принудительный отказ PostgreSQL отдельно не инжектировался.
