# Архитектура GreenStore

Модульный монолит: Next.js App Router / React / TypeScript strict, PostgreSQL 17 / Prisma 7 с PostgreSQL driver adapter. Route Handlers — транспорт; авторизация, каталог, мутации и файлы — серверные модули. Telegram, платежи и доставка ещё не реализованы.

## Границы

- `src/app`: публичные/административные страницы и HTTP-маршруты.
- `src/components/store`: UI витрины; Client Components ограничены интерактивностью.
- `src/components/admin/forms.tsx`: React Hook Form + Zod, доступные labels, блокировка до гидратации, серверные сообщения о сохранении.
- `src/modules/catalog`: DTO, интерфейс асинхронного CatalogRepository и чистые функции фильтров/URL. Демоданные используются только seed и unit-тестами, не публичным приложением.
- `src/server/catalog.ts`: PostgreSQL repository, фильтры/сортировка/пагинация на сервере, только PUBLISHED и активные варианты.
- `src/server/admin-catalog.ts`: транзакционные изменения товаров/вариантов/остатков/картинок/характеристик, категории и настройки.
- `src/server/auth.ts`, `password.ts`, `http.ts`: сессии, scrypt, Origin/size/content-type guards, rate limiting, безопасные ошибки.
- `src/server/storage.ts`: контракт ImageStorage и локальная реализация, декодирование/перекодирование Sharp.
- `src/modules/cart`: версия 1 локального выбора (variantId/quantity), серверное разрешение по `/api/cart/resolve`.

Серверные модули помечены `server-only`. Клиент Prisma в `src/server/client.ts` доступен также CLI, инициализируется лениво, повторно используется одним процессом. Ключи и DB URL не отправляются браузеру. Генерация клиента — `src/generated/prisma`, каталог игнорируется Git.

## База и транзакции

Миграция `202611020001_catalog_admin` создаёт Category, Product, ProductVariant, ProductImage, ProductAttribute, InventoryMovement, AdminUser, AdminSession, AuthThrottle, StoreSetting, AuditLog и UploadAsset. Есть внешние ключи, индексы публичных выборок, уникальные slug/SKU/логин/tokenHash и SQL CHECK на неотрицательные денежные значения/остатки/размеры.

`Product.minPrice` — проекция минимальной цены активных вариантов для эффективной сортировки. Она пересчитывается в той же транзакции, что варианты. Денежные значения — целые копейки (PostgreSQL Int), ввод рублей разбирается десятично без float-умножения.

Товар сохраняется с optimistic version (`updatedAt`) и Serializable isolation. Скалярные поля, варианты, движения остатков, изображения, характеристики и audit фиксируются атомарно. Неизвестный либо чужой variantId отклоняется. Пропущенные варианты деактивируются; продукт удаляется только логически через ARCHIVED. Категории с любыми связанными товарами удалить нельзя.

Seed в транзакции отмечает одноразовую загрузку audit-маркером `seed-catalog-v1`; повторный запуск не откатывает правки, удаления и переименования. Миграции воспроизводятся в каждом чистом тестовом PostgreSQL.

## Сессии и граница доверия

Пароль: scrypt N=32768/r=8/p=1, случайная соль, constant-time сравнение. В cookie — случайный 256-битный токен, в БД только SHA-256. HttpOnly / SameSite=Lax / 8 часов; Secure в production вне loopback. Сессия и active-флаг администратора проверяются на каждой закрытой странице и операции, а не только в layout. Logout удаляет запись и cookie. Счётчики входа в PostgreSQL ограничивают попытки глобально и по логину; просроченные записи очищаются. Неверные логин/пароль получают одинаковое сообщение.

Мутации админки требуют совпадения Origin/Host, и APP_URL, если он задан. Все входные данные проверяются Zod; SQL параметризован через Prisma. Ошибки API не раскрывают SQL, токены и значения конфигурации. Тексты выводятся React как текст, без HTML-вставок. Полноценный внешний аудит и VPS/TLS-конфигурация относятся к последующим этапам.

## Изображения

Защищённая multipart-загрузка ограничена потоковым лимитом тела. JPEG/PNG/WebP ≤5 МБ, ≤20 Мп; Sharp проверяет декодирование, поворачивает, удаляет метаданные и создаёт WebP ≤2000×2000. Имена — UUID, пользовательские пути не используются. Локальные файлы — runtime data за пределами public, не включаются в build trace. Медиа-маршрут выдаёт только валидные ключи с Content-Type, nosniff и immutable cache. Админские URL принимаются только для существующих assets либо собственных иллюстраций.

ImageStorage допускает S3-реализацию. Невостребованные assets сохраняются: автоматическая сборка мусора ещё не реализована, чтобы не сломать повторно используемые логотипы/фото. Бэкап должен включать БД и UPLOAD_DIR.

## Публичный рендеринг и корзина

Витрина и метаданные рендерятся динамически, React cache устраняет повторы запросов внутри одного рендера. После обновления страницы видны изменения админки. Конечный список generateStaticParams/dynamicParams=false удалён: новые опубликованные slug доступны сразу. Listing loading boundary вынесен в `(browse)`, чтобы отсутствующие карточки возвращали 404 до streaming.

Корзина не хранит доверенные цены. Локальные данные ограничены схемой и лимитами; сервер разрешает варианты только из опубликованных товаров и сообщает текущие цены. Исчезнувшие варианты показываются недоступными. При запрете localStorage используется память вкладки. Реального заказа и резервирования пока нет. На этапе 3 создание заказа обязано заново проверить цены/остатки и зафиксировать резервы в транзакции с идемпотентностью.

## Проверки

Vitest: валидаторы, форматирование денег, пароль, фильтры, корзина и базовый UI. Playwright: desktop/mobile витрина и отдельный admin project после них. Драйвер создаёт одноразовую БД/учётную запись/UPLOAD_DIR, применяет миграции и дважды seed. Production smoke отдельно проверяет сохранность сессии, товара, цены, остатка и файла после полного перезапуска процесса; рабочие данные не меняет.
