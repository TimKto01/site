# ЧАСТЬ I. КОНЦЕПЦИЯ ПРОЕКТА

## 2. ОБЩАЯ ИДЕЯ

Название проекта: **GreenStore**.

Это временное техническое название, которое впоследствии можно изменить через настройки магазина.

Тип проекта: интернет-магазин растений, саженцев, хвойных деревьев, кустарников и сопутствующих товаров.

Основной рынок: Российская Федерация.

Валюта: российский рубль (RUB).

Язык интерфейса: русский.

Основная целевая аудитория: обычные покупатели растений, владельцы участков, дачники и садоводы.

Основная задача сайта — сделать покупку растений максимально простой, а обработку заказов практически автоматической.

### Покупатель должен иметь возможность:

1. Открыть сайт с компьютера или телефона.
2. Просматривать каталог растений.
3. Искать товары по названию.
4. Фильтровать каталог.
5. Просматривать подробные характеристики растения.
6. Смотреть фотографии.
7. Выбирать размер и количество растения.
8. Добавлять товары в корзину.
9. Оформлять заказ без обязательной регистрации.
10. Выбирать доступную доставку.
11. Оплачивать заказ онлайн после подключения платёжного сервиса.
12. Получать номер заказа.
13. Проверять статус своего заказа.
14. Получать информацию о доставке.
15. Связываться с магазином.

### Администратор должен иметь возможность:

1. Добавлять и редактировать растения.
2. Загружать фотографии.
3. Создавать категории.
4. Изменять цены.
5. Управлять наличием товаров.
6. Просматривать заказы.
7. Обрабатывать заказы через Telegram.
8. Менять статусы заказов.
9. Просматривать контактные данные покупателей.
10. Создавать отправления через сервисы доставки.
11. Получать данные об оплате.
12. Просматривать статистику продаж.
13. Управлять основными настройками магазина.
14. Экспортировать информацию о заказах.
15. Видеть историю действий с заказами.

В перспективе администратор должен иметь возможность управлять значительной частью магазина даже без открытия сайта — непосредственно через Telegram.

**Backend:**

- Vitest.

**Инфраструктура:**
- Git.

Проект должен быть понятным, обслуживаемым и экономным в размещении.

Предполагается запуск на обычном VPS с возможностью дальнейшего масштабирования.

# ЧАСТЬ V. КОРЗИНА И ОФОРМЛЕНИЕ ЗАКАЗА

## 8. КОРЗИНА

Реализуй корзину с возможностями:

- Добавления товара.
- Удаления товара.
- Изменения количества.
- Отображения цены каждой позиции.
- Подсчёта промежуточного итога.
- Отображения общей суммы.
- Сохранения содержимого при обновлении страницы.
- Перехода к оформлению заказа.

Корзина должна учитывать конкретный вариант товара.

Обязательно проверяй актуальную цену и наличие на сервере непосредственно перед созданием заказа.

Нельзя доверять стоимости товаров, переданной клиентским браузером.

## 9. ОФОРМЛЕНИЕ ЗАКАЗА

Регистрация покупателя не должна быть обязательной.

Форма оформления заказа:

**Контактные данные:**
- Имя.
- Фамилия, если необходима.
- Номер телефона.
- Электронная почта, если необходима для выбранного способа оплаты или уведомлений.

**Доставка:**
- Способ доставки.
- Населённый пункт.
- Адрес доставки или пункт выдачи.
- Почтовый индекс, когда требуется.
- Комментарий к заказу.

**Оплата:**
- Доступные способы оплаты.
- Сумма товаров.
- Стоимость доставки.
- Итоговая стоимость.

Показывай покупателю окончательную сумму до подтверждения заказа.

Никаких скрытых платежей.

### После оформления

Создай уникальный идентификатор заказа.

Пример:

GS-2026-000001.

Покажи покупателю страницу успешного оформления.

На странице должны присутствовать:
- Номер заказа.
- Состав заказа.
- Сумма.
- Статус оплаты.
- Выбранная доставка.
- Инструкция о дальнейших действиях.

Если оплата ещё не подключена, заказ должен оформляться с честно обозначенным режимом ручного подтверждения.

Не показывай ложный статус «Оплачено».

Для оплаченных и отменённых заказов возврат товара в наличие должен учитывать фактический статус возврата и возможность повторной продажи растения.

# ЧАСТЬ VIII. TELEGRAM-БОТ

## 12. НАЗНАЧЕНИЕ

Разработай Telegram-бота для сотрудников магазина.

Бот должен работать совместно с сайтом и базой данных.

Telegram — интерфейс управления, но не единственное место хранения заказов.

### Основные функции

1. Получение уведомления о новом заказе.
2. Просмотр состава заказа.
3. Просмотр текущего статуса.
4. Запуск сборки.
5. Завершение сборки.
6. Оформление отправки.
7. Сохранение трек-номера.
8. Изменение статуса заказа.
9. Просмотр новых заказов.
10. Просмотр краткой статистики.

### Пример уведомления

🌿 НОВЫЙ ЗАКАЗ #1052

Покупатель: Иван

Товары:
Туя Файер Чиф — 2 шт.

Стоимость товаров: 1 100 ₽

Доставка: СДЭК

Статус оплаты: Оплачен

Статус: Ожидает сборки

Кнопки:

[📦 Начать сборку]

[📋 Открыть заказ]

[❌ Отмена / проблема]

Это пример формата. Реализуй настоящие inline-кнопки Telegram.

### После нажатия «Начать сборку»

- Проверить права пользователя.
- Найти заказ.
- Проверить допустимость перехода статуса.
- Изменить статус в базе.
- Добавить запись в историю.
- Обновить сообщение Telegram.
- Отразить изменения в административной панели.

### Безопасность бота

- Управлять заказами могут только разрешённые Telegram ID.
- Список администраторов задаётся конфигурацией.
- Проверка доступа обязательна для каждой команды и callback.
- Telegram username не использовать как надёжный идентификатор доступа.
- Не выводить токены и ключи в логах.

- Для просмотра полной информации использовать защищённую страницу заказа либо строго ограниченную административную функцию.
- Повторные нажатия кнопок не должны выполнять действие дважды.

### Дополнительное меню

### Техническая архитектура

Используй отдельный процесс Telegram-бота.

Для локальной разработки допускается long polling.

Обработку бизнес-операций вынеси в общие сервисы, чтобы веб-интерфейс и Telegram не содержали две разные реализации одной операции.

Для надёжной отправки уведомлений используй механизм outbox либо аналогичный способ, не допускающий потери событий при временных сбоях Telegram.

1. Покупатель оформляет заказ.

9. Telegram-бот получает уведомление.
10. Заказ становится доступен для сборки.

- Используй ключи идемпотентности.
- Проверяй сумму и валюту.
- Защищай обработчики уведомлений.
- Учитывай повторную доставку webhook.

- Не имитируй успешную оплату в реальном режиме.
- Отделяй тестовый режим от производственного.
- Обрабатывай отменённые и неуспешные платежи.
- Предусмотри корректную обработку возвратов.

Продумай интеграцию с подходящим механизмом фискализации, если он требуется продавцу.

- READY_TO_SHIP — готов к отправке.

Это нормально.

### Переходы

Реализуй валидатор допустимых переходов.

Запрещай нелогичные переходы, например:

- Отправить не собранный заказ без специального действия.
- Отметить неоплаченный заказ оплаченным без подтверждения платежа или разрешённой ручной операции.
- Повторно провести оплату уже оплаченного заказа.
- Создать два одинаковых отправления из-за повторного нажатия кнопки.

Все изменения статусов должны отражаться в истории.
