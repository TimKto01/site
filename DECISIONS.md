# Технические решения

## 2026-11-02

- Сохранён существующий Git checkout; новый worktree не нужен.
- Node 24 LTS, npm 11; зависимости фиксируются точными версиями и package-lock.json.
- Next.js 16.4.4 / React 19.3.1 / Tailwind 4.3.3; Prisma 7.10.1 вместо latest 8 RC.
- shadcn/ui: локальные компоненты, Radix Slot, CVA, компоненты на CSS-переменных; конфигурация components.json.
- PostgreSQL 17 в Docker Compose, локальный порт, пароль в игнорируемом .env; реальных секретов в Git нет.
- Этап 1 использует демонстрационные данные и localStorage. Оплата и оформление заказов до этапа 3 недоступны.
- Vitest для поведения модулей/компонентов, Playwright для браузерных сценариев.

## Этап 1 — 2026-11-02

- Каталог — серверный repository с контрактом для будущей PostgreSQL-реализации; 12 демотоваров / 24 варианта, пагинация 8, фильтры хранятся в URL.
- Для отсутствующих статических демокарточек dynamicParams=false обеспечивает 404 до streaming. Настройку обязательно пересмотреть при добавлении реальных записей.
- Корзина версии 1 хранит variantId/quantity, SSR-safe useSyncExternalStore, validation через Zod, fallback в памяти при запрете хранилища.
- Полный checkout до этапа 3 не показывается: disabled action с явным объяснением, сумма только товаров.
- SVG-иллюстрации созданы для проекта, фотографии магазинов не использованы. Демо явно обозначено, вымышленных отзывов/реквизитов нет.
- allowedDevOrigins ограничен локальным 127.0.0.1 для Next.js dev/HMR; внешняя сетевая политика не менялась.
- Не включать React Hook Form и интеграционные SDK в клиентские bundles до появления соответствующих форм/операций.

## Этап 2 — 2026-11-02

- Публичная часть переключена на асинхронный PostgreSQL repository. Демонабор оставлен только для одноразового seed и unit-тестов. DB outage не подменяется фиктивными товарами.
- Только необходимые текущему этапу модели: каталог, сессии, файлы, настройки, audit и движения остатков. Order/Payment/Shipment будут введены вместе с соответствующими операциями, а не пустыми таблицами заранее.
- Архив вместо физического удаления продукта, деактивация вместо удаления использованного варианта; связанные категории защищены FK и прикладной проверкой.
- Цены — копейки, ручной ввод рублей разбирается десятично; денежный formatter сохраняет копейки. minPrice обновляется атомарно. Устаревшая версия редактирования — 409.
- Локальные административные учётные записи: scrypt, серверные opaque sessions и SHA-256 в БД. Нет публичной регистрации и стандартного пароля. CLI создаёт случайный локальный пароль, если он не передан через защищённое окружение, и сохраняет его только в игнорируемом файле 0600.
- CSRF-защита Origin/Host и опциональный canonical APP_URL; счётчики входа в PostgreSQL, без доверия произвольному X-Forwarded-For.
- Фотографии декодируются Sharp, метаданные удаляются, сохраняется WebP по UUID вне public. Произвольные URL/пути и загружаемые SVG запрещены. Файлы не включаются в build trace как исходный код.
- Формы админки недоступны до гидратации, что предотвращает потерю быстрого ввода. Подтверждение сохранения связано с завершённым API-запросом; прежнее сообщение скрывается при редактировании.
- Playwright и production smoke работают в одноразовых БД; исходный каталог и локальный пароль владельца не используются в тестовых мутациях. Seed повторяется и проверяется на отсутствие перезаписи.
- Админка не показывает фиктивную статистику продаж; заказы и коммерческие интеграции остаются следующими этапами.
